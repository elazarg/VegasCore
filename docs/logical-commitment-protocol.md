# Logical commitment protocol experiment

`Interaction.LogicalCommitment` is a one-binding semantic kernel. It tests how
much of a pending-message execution can be forgotten before the strategic
argument becomes unsound.

The kernel retains competing handles, immutable private meanings, the first
accepted handle, locally sent and delivered *logical* claims, a public
logical-claim ledger, public acceptance receipts, and the terminal distinction
between an opening and attributed fallback. It omits message identifiers, the
pending queue, replay implementation, numerical clocks, deadlines, and
service. A claim may be visible in one player's inbox before it is included.
Inclusion always records the logical claim and its receipt, including
rejection. This has the same local-versus-shared shape as native sent/inbox
versus ledger/receipts, but it is not yet an exact observation match.

In particular, `Claim.malformed` deliberately merges distinguishable rejected
native payloads. A wrong-node opening, cleartext payload, and malformed payload
can carry different values or tags in the native ledger and thereby influence
a later policy. The kernel is a quotient; a refinement must show that those
forgotten distinctions are strategically irrelevant for the policies under
consideration, or refine `Claim`. Adding an unrestricted residual-history
signal would only rename the native state and is not part of this experiment.

The transition laws establish the following local facts:

- exposure changes neither the ledger nor the result;
- inclusion changes neither local inboxes nor sent lists, and appends exactly
  one public ledger claim and one receipt;
- the first valid selection is stable;
- selecting a fresh handle fixes it as unopenable, while selecting a prepared
  handle preserves its value;
- an opening resolves only the selected, owner-scoped, openable handle;
- rejected malformed traffic remains in the ledger and can be followed by an
  attributed fallback; and
- an already resolved result is not changed by later inclusions.

## Representative abstractions

A prepared opening trace can abstract as

```text
prepare(owner, h, v)
submit(owner, open(owner, h, v))
expose(observer, open(owner, h, v))
include(select(owner, h))       -- accepted
include(open(owner, h, v))      -- accepted, result = opened(v)
```

The exposure is deliberately earlier than inclusion. This ordering is a
possible deviating trace. It is not generated by the honest compiler,
whose publication barrier must be proved separately.

Competing candidates can abstract as

```text
prepare(owner, h1, v1)
prepare(owner, h2, v2)
submit(owner, select(owner, h2))
include(select(owner, h2))      -- h2 wins
submit(owner, select(owner, h1))
include(select(owner, h1))      -- public rejection
submit(owner, open(owner, h1, v1))
include(open(owner, h1, v1))    -- public rejection
submit(owner, open(owner, h2, v2))
include(open(owner, h2, v2))    -- result = opened(v2)
```

An accepted unprepared candidate can abstract as

```text
submit(owner, select(owner, hFresh))
include(select(owner, hFresh))  -- hFresh becomes permanently unopenable
submit(attacker, malformed(attacker))
include(malformed(attacker))    -- public rejection
submit(owner, open(owner, hFresh, v))
include(open(owner, hFresh, v)) -- public rejection
settleQuit(owner)               -- result = quit
```

The last event is an operational settlement attributed to the owner. A native
timeout is caused by the environment's clock action and may occur after the
owner's last opportunity to act. Consequently this trace does **not** prove
that the owner chose to quit at the timeout, or that the owner observed the
last pre-timeout state.

## What a concrete refinement still owes

`Action.RealizableAt` is only a no-spontaneous-claim check. It requires a fresh
submission to carry its author's identity, permits relaying only a claim the
broadcaster already knows, and requires exposed or included claims to have a
recorded submission. It intentionally does not claim that a pending copy still
exists. A candidate-runtime refinement must additionally prove occurrence-wise
availability and consumption from the actual message pool.

More importantly, a strategic refinement needs a *relative-information
contract*. Equality of native observations must imply equality of their
logical projections; this establishes only that the abstraction is
observation-local. It is not enough for backtranslation. After admissible
auxiliary responses and random tapes are fixed, native histories in the same
logical-view fiber must induce the same abstract next-command law. A different
possible route constructs a logical policy from conditional native command laws
given the logical local history. That route must prove the conditional-independence
and consistency properties needed to retain the unchanged opponents and the joint
execution law; simply defining a conditional distribution does not prove
simulation. Private logical command memory must also be retained when the
current public/local view alone is insufficient. Otherwise forgotten clocks, message identifiers,
or rejected-payload details can change native choices that no logical policy
can reproduce.

For the owner, permitted differences may depend only on handles and values
already available in that owner's native private commands or message view.
Every abstract `expose` must be justified by an actual inbox delivery, every
`submit` by an actual sent-list entry, and every `include` and receipt by the
corresponding public ledger and receipt occurrence. In particular, the
abstraction may not choose an exposed value by reading the private candidate
table.

The exact transport obligations and the utility obligation are different:

1. A trace abstraction should prove the observation correspondence above,
   public selection/opening agreement, and that every mapped fallback has
   runtime owner attribution and valid settlement.
2. The strategic proof must construct a logical deviation from the player's
   actual information before its last relevant opportunity, or use a stopped
   coupling that does not pretend the timeout itself was a player choice.
3. A separate informed-quitting inequality must bound each fallback fiber by
   a legal graph deviation. Honest normal-completion utilities must agree
   exactly.

Only after those obligations are proved does this layer supply an edge suitable
for `GameTheory.GameForm.UtilitySimulation`; composition with the source-to-
graph edge can then use `UtilitySimulation.trans`.

This one-binding kernel does not establish joint observational safety across
program sites. A falsifying cross-site test is a pair of executions that agree
at the current binding but differ at another site's private candidate, followed
by delivery or inclusion whose payload or command distribution reveals that
difference before the current binding resolves. If the two resulting local
views or next-command laws differ without corresponding native knowledge, then
per-binding simulations cannot be composed; a graph-wide relation retaining
all simultaneously knowable handles is required.

The current experiment therefore proves useful semantic laws, but it is not
yet a composable graph-to-runtime boundary. It removes clocks and queue
mechanics from the binding kernel while leaving precisely stated transport,
relative-information, cross-site, and quitting-utility obligations.

`InteractionTests/LogicalCommitment.lean` checks early-opening visibility with
public rejection, and selection among competing prepared handles. The module
is built independently of the Vegas compiler: no active compiler theorem depends
on it, and it is not an additional claimed compilation edge.

The [native refinement assessment](logical-commitment-refinement-assessment.md)
identifies admission and private-recall information missing from this kernel.
The [gated single-site experiment](logical-commitment-gated-experiment.md) tests
those additions against actual candidate-runtime transitions and distinguishes
an operational projection from a strategic simulation.
