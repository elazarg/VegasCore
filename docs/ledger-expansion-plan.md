# Runtime expansion proof plan

The current endpoint is native public-message execution. Further runtime work
should extend the active strict sealed-message edge by small, independently
checked edges.

The manuscript's former split sets a useful strength target, but its fused
implementation is archived. Meeting that target on the strict edge requires
both its strategic strength and its source-outcome observation scope;
the current completion/public-output projection alone does not imply every
utility bound over full terminal source environments. Native outcomes retain
complete policy executions. A full source decoder must be constructed from
that actual state/history, without adding a source interpreter or proof witness
to the target's execution. Eligibility and service hypotheses must also be
discharged by compilation or stated as explicit runtime capabilities.

1. Prove the whole-prefix source deviation extraction for the active pending
   message policy game. Runtime policy inputs include each player's visible
   inbox, public ledger, sent messages, receipts, and local history.
2. Prove the resolution law that maps malformed traffic or withholding, after
   the stated fairness/timeout condition, to the source program's explicit
   nullable quit; then linearize arbitrary finite-support randomized policies.
3. Compose the honest source law, deviation mixture, public-outcome guarantee,
   and same-epsilon Nash equivalence for the actual pending-message game.
4. Add adaptive public scheduling as a separate edge. Its scheduler action is
   public; the required hypothesis is data-independence from unopened payloads,
   together with explicit delivery and deadline fairness.
5. Replace ideal commitments or entropy only with named concrete schemes and
   appropriate computational or distributional guarantees.
6. Introduce a ledger model for admission, ordering, clocks, receipts,
   finality, balances, and failure behavior.
7. Lower the same identified application artifact to a chosen VM and prove
   whole-handler execution, including malformed input and exceptional paths.

At each checkpoint, distinguish executable construction, local handler laws,
support refinement, progress, observation simulation, and strategic
backtranslation. A later stage should not be advertised by importing an
unconnected backend component.

## Current proof inventory

The fixed-windowed and delivery proof material is archived for reference. The
active strict edge currently closes native prefix refinement, terminal source
reconstruction, and ideal-service hiding. The next strategic milestone is to
instantiate `SealedCompilation.StrategicCertificate` for the concrete pending
message policy game.

The active runtime model already includes opaque commitments, cleartext
rejection, public pending messages, delivery, inclusion, replay, and timed
expiration adapters. These facts are operational and support-level. They do
not by themselves identify a runtime policy with a source policy: pending
payloads and delivery timing are additional inputs, so the pending-message
backtranslation must prove the required observation or mixture law explicitly.

Progress and strategic simulation remain separate. A resolving reference
service can prove an honest forward law. Arbitrary scheduling requires causal
simulation from each player's declared observation. Deadline liveness further
requires that timely persistently valid messages receive a fair opportunity
before expiration; permissionless expiry alone supplies no such guarantee.
